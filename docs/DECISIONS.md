# Технические решения

Журнал решений, принятых по умолчанию. Новые записи добавляются в конец.

## Этап 1 — каркас и дизайн-система

### Название и идентификаторы
- Рабочее название **Aurora VPN** (бирюзово-фиолетовый градиент напоминает полярное сияние).
- Dart-пакет `aurora_vpn`, Android `applicationId` `dev.aurora.aurora_vpn`. Всё переименовывается в одном месте до первого релиза.

### Тулчейн
- Flutter **3.47.7** stable (Dart 3.13.5). Все инструменты лежат portable-версиями в `D:\dev`
  (Flutter, JDK 17 Microsoft Build, Go 1.27.2, MinGit, Android cmdline-tools), кэши pub, Gradle и Go тоже там.
  `scripts/dev_env.ps1` настраивает PATH для текущей сессии. Корень можно переопределить через `AURORA_TOOLS`.
- Аналитика Flutter и Dart отключена (`flutter config --no-analytics`, `dart --disable-analytics`).

### Зависимости
| Задача | Выбор | Почему |
|---|---|---|
| State | `flutter_riverpod` 3.x, без кодогенерации | Явные `Notifier`/`Provider`, меньше build_runner-магии |
| Навигация | `go_router` 18, `StatefulShellRoute` | Каждая вкладка хранит свой стек |
| Иконки | **Lucide** (`lucide_icons_flutter`) | `phosphor_flutter` 2.1.0 (последний релиз 05.2024) не компилируется на Flutter 3.47: `IconData` стал `final`. У Lucide есть начертания 100–600 |
| Шрифт | Manrope, вариативный TTF из google/fonts (OFL), лежит локально | Стили явно задают ось `wght` через `fontVariations` |
| Настройки | `shared_preferences` за интерфейсом `SettingsRepository` | Только нечувствительные данные; секреты пойдут в secure storage (этап 3) |
| БД (этап 3) | drift (SQLite) | Isar 3 фактически не поддерживается и плохо работает с AGP 8 |
| Окно Windows | `window_manager` | Кастомная заголовочная панель, минимальный размер 420×720 |

### Архитектура
```
lib/
  core/           платформа, l10n-расширения
  domain/         сущности и интерфейсы репозиториев (без Flutter)
  data/           реализации репозиториев, парсеры, платформенные адаптеры
  application/    контроллеры и use cases (Riverpod Notifier)
  presentation/   theme/, widgets/ (дизайн-система), shell/, router/, features/<screen>/
  l10n/           ARB-файлы; сгенерированный код в l10n/gen
```

### Навигация
- Пять вкладок на всех платформах: Главная, Серверы, Маршруты, Логи, Настройки.
  Material 3 допускает 5 пунктов в нижней панели, а единая структура упрощает deep-link и тесты.
- Windows всегда использует `NavigationRail`. Android переключается на rail при ширине ≥ 840 dp (планшеты).
- Вкладки переключаются кросс-фейдом с небольшим сдвигом (`AnimatedBranchContainer`).
  Неактивные ветки остаются смонтированными, их тикеры отключены.

### Дизайн-система
- Токены: радиусы 8–28, шкала отступов кратна 4, длительности 150/260/420 мс.
- `AppColors` (ThemeExtension) хранит градиенты, стеклянные поверхности и цвета статусов подключения. По умолчанию тёмная тема.
- Компоненты: `AppCard` (solid / elevated / glass / selected с градиентной обводкой), `GradientButton`, `SoftButton`,
  `AppIconButton`, `Pressable`, `StatusPill`, `IconBadge`, `SectionHeader`, `EmptyState`, `Skeleton`,
  `StaggeredEntrance`, `SettingsGroup`/`SettingsTile`, `PageScaffold`, `AppBackground`.
- Свечение фона рисуется радиальными градиентами, без blur-фильтров: дёшево и без перерастеризации при прокрутке.
- Живая витрина компонентов: Настройки → Дизайн-система.

### Тесты
- Golden-тесты (`test/golden`, тег `golden`) с реальными шрифтами, загружаемыми из FontManifest.
  Регенерация: `flutter test --update-goldens --tags golden`.
  Рендеринг шрифтов зависит от ОС, поэтому в CI golden-тесты запускаются только на Windows-раннере.

## Этап 2 — UI на моках

### Слои и моки
- Домен: `ServerProfile`, `Subscription`/`SubscriptionUsage`, `VpnState`/`TrafficSample`, `LogEntry`,
  `RoutingSettings`, `InstalledApp` и интерфейсы `ServerRepository`, `SubscriptionRepository`,
  `InstalledAppsSource`, `VpnCoreController`.
- Композиция в `lib/application/di.dart`. Пока подключены in-memory репозитории и `MockVpnCoreController`
  (реалистичные переходы состояний, трафик, логи, URL-тест). Этапы 3–5 подменят только этот файл.
- Демо-данные (`data/mock/demo_data.dart`) используют только зарезервированные домены `example.*` (RFC 2606).
  На этапе 3 они уходят из продакшен-пути и остаются только в тестах. Реальных серверов в коде нет.

### Поведение
- Выбранный сервер хранится в prefs. Если ничего не выбрано, берётся первый из избранного, затем первый вообще.
- Тест задержки идёт параллельно, пулом из 8 воркеров. Сортировка по задержке ставит недоступные в конец.
- Логи — кольцевой буфер на 2000 строк. Провайдер логов активен с запуска приложения
  (иначе строки до первого открытия вкладки терялись — найдено тестом).
- Время берётся из одного источника `nowProvider` (`package:clock`), поэтому таймер сессии и время логов
  детерминированы в тестах.
- Kill switch на Android открывает системные настройки always-on VPN (подключается на этапе 6).
  На Windows это переключатель, который работает в режиме TUN.
- Раздельное туннелирование по приложениям — только Android. На Windows пункт виден, но помечен «Доступно в Android-версии».
- Дефолты: MTU 9000 (как у sing-box TUN), DNS — DoH Cloudflare, режим маршрутизации «По правилам» с обходом LAN.

### UI
- Кнопка подключения — CustomPainter с плавной интерполяцией палитры между состояниями,
  пульсирующими кольцами (connected) и вращающейся дугой (connecting). Контроллеры анимаций
  работают только когда нужны. Haptic: medium по тапу, heavy при подключении.
- Sparkline плавно сдвигается при поступлении новой точки (1 Гц данных → 60 fps анимации).
  При подключении история заполняется нулями, чтобы линия сразу шла на всю ширину.
- Логи — моноширинный JetBrains Mono (OFL, локально), висячий отступ, список `reverse` прилипает к низу.
- Избранное — заполненная звезда Material (в Lucide нет залитых глифов).

## Этап 3 — парсеры, хранилище, подписки, генератор конфигов

### Модель
- `OutboundConfig` — одна плоская неизменяемая модель для всех 7 протоколов: транспорт (tcp/ws/grpc/h2/httpupgrade)
  и TLS (none/tls/reality + uTLS). JSON-сериализация нужна для зашифрованного хранения. Отдельный класс на каждый
  протокол удвоил бы код парсеров, хранилища и редактора без выигрыша.
- `ServerProfile.identity` = протокол + хост + порт + имя. При обновлении подписки сервер с той же identity
  сохраняет `id`, а с ним избранное и текущий выбор.

### Парсеры
- Ссылки: vless, vmess (base64 JSON), trojan, ss (SIP002, SIP022 для 2022-шифров, legacy base64), hysteria2/hy2
  (obfs salamander, port hopping — берётся первый порт), tuic, wireguard/wg, `happ://add/<url>`.
  Authority и query разбираются вручную, без `Uri.parse`: IPv6 в скобках, пароли со спецсимволами, `+` остаётся `+`.
- Не поддерживается (с понятной ошибкой): xhttp/kcp/quic-транспорты (их нет в sing-box), плагины Shadowsocks,
  зашифрованные `happ://crypt…` (проприетарный ключ Happ).
- Подписки: формат определяется автоматически — sing-box JSON (`outbounds` + `endpoints`), список ссылок,
  base64-список (стандартный и URL-safe, с переносами), Clash/mihomo YAML (`proxies`).
- Заголовки: `subscription-userinfo`, `profile-update-interval`, `profile-title` (в т.ч. `base64:`),
  `content-disposition` как запасной источник имени, `support-url`. Интервал из заголовка используется,
  пока пользователь не выбрал свой в форме.
- User-Agent `AuroraVPN/0.1`: клиент представляется честно, без маскировки под чужие приложения.
  Панели на неизвестный UA отдают base64-список, его мы разбираем.

### Хранилище
- drift (SQLite), таблицы `subscriptions` и `servers`, `ON DELETE CASCADE`.
- Учётные данные серверов (UUID, пароли, ключи, параметры TLS) и URL подписок (в них токены) шифруются
  AES-256-GCM (`package:cryptography`). Случайный 256-битный ключ создаётся один раз и хранится в
  `flutter_secure_storage` (Android Keystore / Windows DPAPI). Имя, хост, порт и протокол хранятся открыто,
  они нужны для списков и поиска.
- Строки, которые не удалось расшифровать (например, после сброса хранилища ключей), пропускаются, без падения.
- База лежит в каталоге application support (на Windows — `%APPDATA%`, не «Документы»).
- Демо-данные больше не попадают в продакшен. Приложение стартует пустым, демо используется только в тестах.

### Генератор sing-box
- Целевая версия ядра **1.14.3**. Формат 1.12+: DNS-серверы нового вида (`type: https/tls/udp/local`),
  `route.default_domain_resolver`, rule actions (`sniff`, `hijack-dns`, `reject`), WireGuard через `endpoints`.
  Устаревших outbound'ов `block`/`dns` нет.
- Каждая комбинация протокол × транспорт × режим проверяется настоящим `sing-box check`
  (`test/integration_core`, тег `core`): 12 конфигов, 0 ошибок, 0 предупреждений.
- Rule-set'ы (geoip-ru, geosite-category-ru, geosite-category-ads-all) **локальные**. Они скачиваются
  `fetch_core` с закреплённых коммитов, кладутся в ассеты и подключаются как `type: local`. Ядру не нужно ходить
  на GitHub при старте: запуск быстрее, работает офлайн, нет лишних внешних запросов.
- Если IPv6 выключен, туннель всё равно захватывает v6 и отклоняет его, чтобы IPv6 не утекал мимо VPN.
  Для DNS при этом стоит `ipv4_only`.
- Kill switch на Windows = `strict_route` в режиме TUN. На Android `strict_route` включён всегда.

### Задержка
- TCP-handshake до сервера без DNS-резолва (`TcpLatencyTester`) работает без ядра и без прав.
  Для UDP-протоколов (Hysteria2, TUIC, WireGuard) так не измерить: они пропускаются, URL-тест через ядро
  появится на этапах 4–5.

### Загрузка ядра
- `scripts/fetch_core.ps1`: sing-box.exe (GitHub SagerNet), wintun.dll (wintun.net), rule-set'ы.
  SHA-256 закреплены в `scripts/core_versions.json` (хэш wintun сверен с опубликованным на сайте), при
  несовпадении скрипт останавливается. Бинарники и `.srs` в `.gitignore`.
- В релизах sing-box нет готового `libbox.aar`: на этапе 4 он собирается из исходников через gomobile.

### Импорт
- Один `ImportService` для буфера обмена, QR (`mobile_scanner`, только Android) и deep-link (`app_links`,
  Android intent-filter для всех схем). Одиночный http(s)-URL из буфера открывает форму подписки, всё остальное
  импортируется сразу. Повторно ту же подписку не добавляет.

### Material You
- Dynamic color (цвета из обоев Android 12+) **не добавляем** — решение заказчика. Палитра всегда фирменная.


## Этап 4 — ядро на Android (libbox + VpnService)

### Сборка libbox
- `scripts/build_libbox.ps1` / `.sh`: исходники sing-box по закреплённому тегу, gomobile-форк `sagernet/gomobile`
  той версии, что указана в `go.mod` sing-box. `-androidapi 24`, ABI arm64 / armv7 / x86_64.
- Теги сборки: только нужное клиенту (`with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api` + linkname-теги).
  Без Tailscale, OpenVPN, OpenConnect, USB/IP и naive: в официальном наборе их много, AAR был бы в разы больше.
- В Windows-версии gomobile падает на скрытых переменных окружения `=C:=…`. Скрипт под Windows собирает gomobile
  с однострочной правкой `env.go`: такие переменные пропускаются так же, как в соседнем цикле. Если upstream изменит
  файл, скрипт явно остановится, а не наложит правку молча.
- PowerShell 5.1 разрывает аргументы вида `-javapkg=io.x` на точке, поэтому все флаги gomobile в кавычках.
- NDK один на всё: `28.2.13676358` (та же версия, что у Flutter), а не рекомендованный sing-box 28.0. Сборка проверена.

### Нативный слой (Kotlin, `dev.aurora.aurora_vpn`)
- `AuroraVpnService`: VpnService + `PlatformInterface` + `CommandServerHandler` libbox 1.14.3. Сервер команд работает
  через unix-сокет в приватном каталоге приложения, TCP-порт не открывается.
- Монитор сети по образцу sing-box-for-android / shadowsocks-android: `registerBestMatchingNetworkCallback` (31+) или
  `requestNetwork` (28–30), чтобы видеть реальную сеть под VPN. Локальный DNS через `DnsResolver` (29+).
- Активный конфиг пишется в `filesDir/active-config.json`, а не в Intent. Always-on VPN перезапускает туннель
  без UI; в манифесте `SUPPORTS_ALWAYS_ON`.
- Foreground-сервис `specialUse` (Android 14+), уведомление: имя сервера, скорость ↓/↑ (раз в 2 с), кнопка «Отключить».
- Мост: `aurora/vpn` (prepare / start / stop / state / openVpnSettings), `aurora/vpn/events` (статус, трафик, логи из
  `CommandClient`), `aurora/apps` (список приложений с иконками для раздельного туннелирования).
- Kill switch на Android — системный: кнопка в настройках открывает экран VPN, где включаются «Постоянный VPN» и
  «Блокировать соединения без VPN». Приложение не может включить это само, это ограничение Android.
- Резервное копирование данных приложения запрещено (`allowBackup=false`, data extraction rules): конфиги и ключи
  не уходят в облако и при переносе на новое устройство.

### Размер APK
- Нативные библиотеки сжаты (`useLegacyPackaging = true`): `libbox.so` 57 → ~20 МБ, APK на одну ABI ~33 МБ.
  APK скачивают напрямую, поэтому размер загрузки важнее экономии при установке.

### Логи
- Маскировка (`LogMask`) применяется ещё до UI, буфера обмена и экспорта: UUID, `password/token/uuid/…=значение`,
  учётные данные в URL, длинные base64/hex-блоки.

### Windows-разработка с разных дисков
- Проект на C:, pub-кэш на D: — инкрементальная компиляция Kotlin падает на путях с разными корнями, поэтому
  `kotlin.incremental=false`.

## Xray-core, XHTTP, HWID (между этапами 4 и 5)

### Гибридное ядро sing-box + Xray
- sing-box остаётся фронтом: TUN, DNS, маршрутизация, split-tunnel, kill switch. Серверы, которым нужен Xray
  (XHTTP, VLESS-шифрование, mux, sockopt/fragment, цепочки `dialerProxy`, hysteria из Xray JSON), sing-box отправляет
  в Xray-core через SOCKS5 на 127.0.0.1.
- Мост: **случайный порт и случайные логин и пароль на каждую сессию**. Другие приложения не могут найти и
  использовать локальный прокси (в РФ встречается сканирование localhost для обнаружения VPN).
- Против петли трафика Xray: на Android приложение исключается из TUN (если нет include-списка), на Windows
  в режиме TUN `process_name: xray.exe → direct`.
- Android: один gomobile-AAR из модуля `native/corebridge` (libbox + свой пакет `xraybridge`). Два отдельных
  gomobile-AAR в одном APK конфликтуют. Версии: sing-box 1.14.3, Xray-core 26.3.27 (`v1.260327.0`), APK +~5 МБ.
- Windows: `xray.exe` из официального релиза, SHA-256 сверяется и с опубликованным `.dgst`, и с закреплённым значением.
- Ядро собирается **Go 1.26.8** (`GOTOOLCHAIN`), как официальные сборки sing-box: `badtls`/linkname читает
  внутренние структуры `crypto/tls`. Сборка на Go 1.27 — вероятная причина вылета при подключении.
- Xray JSON: серверы, совместимые с sing-box, конвертируются в общую модель. Остальные хранят **исходный outbound
  без изменений** (в зашифрованном поле), поэтому десятки параметров XHTTP (`extra`, xmux, padding…) не теряются.
- Конфиги проверяются настоящими `xray run -test` и `sing-box check` (`test/integration_core`).

### Заглушки провайдеров
- Если все серверы в ответе — заглушки (порт ≤ 1, 0.0.0.0, localhost…), это `clientNotSupported`, и в UI
  выводится текст самого провайдера («Клиент не поддерживается»). HTML-страница и неизвестный формат тоже дают
  отдельные понятные сообщения.
- Выдавать себя за другой клиент (Happ и т.п.), чтобы обойти ограничения провайдера, приложение **не будет**.

### HWID
- Заголовки `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model` (формат Remnawave). HWID — случайные 128 бит,
  генерируются один раз на установку, это не серийный номер и не IMEI. Отправляются только на добавленные
  пользователем URL подписок. По умолчанию включено (иначе подписки с лимитом устройств не работают), выключается
  в настройках. User-Agent остаётся честным: `AuroraVPN/<версия>`.

### Здоровье соединения
- Если при «Подключено» ядро пишет `open connection … [proxy]: lookup …: NXDOMAIN`, на главной появляется
  «Адрес сервера не найден», при ≥5 ошибках за 15 с — «Сервер не отвечает». Плашка сбрасывается при
  переподключении или через 30 с без ошибок.

## Этап 5 — Windows

- Ядро — дочерние процессы `sing-box.exe` (и `xray.exe` для серверов, которым нужен Xray) из папки `core` рядом с
  exe. Запуск считается успешным по строке `sing-box started` (таймаут 20 с), иначе — ошибка с текстом ядра.
- Режимы: **системный прокси** (по умолчанию, без прав администратора) и **TUN** (wintun, нужны права администратора;
  без них — понятная ошибка и кнопка «Перезапустить от имени администратора»).
- Системным прокси управляет приложение (реестр WinINet + `InternetSetOption`), а не sing-box
  (`set_system_proxy: false`): так прокси гарантированно снимается при остановке, выходе и после аварийного завершения.
  Исключения — локальные сети (`10.*`, `192.168.*`, `172.16–31.*`, `<local>`).
- Порты mixed-inbound и Clash API выбираются ОС заново на каждую сессию, Clash API защищён случайным секретом.
  Статистика скорости — поток `/traffic`.
- PID ядра пишется в `%LOCALAPPDATA%\AuroraVPN\run\core.pids`. При старте приложения `recover()` завершает
  «осиротевшее» ядро и снимает оставленный нами прокси (если приложение было убито).
- Петля Xray: правило `process_name xray.exe → direct` в sing-box.
- Один экземпляр: именованный mutex в `main.cpp`; второй запуск показывает окно первого. Ссылки
  `vless://`/`happ://` передаются в запущенный экземпляр через `app_links`.
- Трей (`tray_manager` 0.5.x — новые версии требуют C-компилятор для nativeapi): подключить/отключить, показать, выход.
  Крестик окна сворачивает в трей; выход только из меню трея (сначала останавливается ядро).
- Автозапуск — значение в `HKCU\…\Run` с флагом `--minimized` (сразу в трей). Пакет `launch_at_startup` не
  используется: в pub разрешался в устаревшую версию.
- Нативная часть Windows (C++/CMake) собирается только в CI (локально нет Visual Studio).

## Этап 6 — поведение и настройки

- «Подключаться при запуске»: после загрузки списка серверов, только если туннель ещё не поднят (служба Android
  может пережить закрытие UI, Always-on VPN поднимает её сам) — проверка через `VpnCoreController.isRunning()`.
  На Windows вместе с автозапуском (`--minimized`) приложение подключается прямо из трея.
- Изменения применяются на лету: другой/отредактированный сервер, маршрутизация, DNS, MTU, IPv6, kill switch,
  уровень логов, режим Windows. Во время подключения ядро перезапускается с новым конфигом (дебаунс 0,7 с).
- Экспорт логов: весь буфер (фильтр не учитывается — для диагностики нужна полная картина), заголовок с версией
  и ОС. Windows — файл в «Загрузках». Android — `cache/logs` + системное меню «Поделиться» через `FileProvider`
  (без разрешений на хранилище). Сообщения уже замаскированы (UUID, пароли, токены).

## Этап 7 — иконки и сплэш

- Все иконки (Android legacy + adaptive + monochrome для тематических иконок Android 13, exe, трей) рендерятся
  из той же геометрии, что и логотип в приложении (`AppLogo.paintMark`), утилитой
  `tool/icons/render_icons_test.dart`. Без `flutter_launcher_icons`/`flutter_native_splash`: меньше зависимостей,
  и иконки не расходятся с логотипом.
- ICO собираются из PNG-кадров (поддерживается с Windows Vista). На мелких размерах знак крупнее.
- Трей: цветной знак при подключении, серый — когда отключено (виден и на светлой, и на тёмной панели задач).
- Сплэш тёмный всегда (приложение тёмное по умолчанию): без белой вспышки до первого кадра; Android 12+ —
  системный SplashScreen с тем же знаком.

## Этап 8 — сборка и выпуск

- `scripts/build_android.sh`: libbox (если нет), правила, APK по ABI + универсальный → `dist/` с версией в имени.
- `scripts/build_windows.ps1 [-Installer]`: ядро, сборка, portable zip, установщик → `dist/`.
- Установщик Inno Setup 6 (а не MSIX): MSIX требует подписанного пакета и плохо дружит с дочерними процессами,
  реестром автозапуска и системным прокси. Установка по умолчанию на пользователя (без UAC), в диалоге — для всех.
  Задача «Открывать ссылки vless://, happ://…» регистрирует URL-протоколы; при удалении убираются протоколы,
  автозапуск и `run`-файлы, настройки и база серверов остаются. Перед установкой/удалением просит закрыть
  приложение (mutex), чтобы прокси снялся корректно.
- CI на тег `v*` создаёт **черновик** релиза со всеми файлами; публикация — вручную после проверки.
- Exe не подписан сертификатом (SmartScreen предупредит при первом запуске) — подпись кода платная, добавляется
  секретами CI, когда появится сертификат.
